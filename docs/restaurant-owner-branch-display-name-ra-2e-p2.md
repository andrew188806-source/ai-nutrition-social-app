# RA-2E-P2 branch display-name activation

The fixed same-origin route is `GET|POST /api/restaurant/branches/[branchId]/display-name`. It uses only the frozen P1 preview and mutation RPCs with canonical Restaurant session claims. Browser data remains bounded; audit IDs and database details stay server-side.

The name destination is outer-trimmed only, is 1–80 Unicode code points, preserves interior whitespace, and rejects C0/C1 controls. A rename requires confirmation and may update existing public presentation only where existing parent publication gates already permit it. It never changes status, GEO/address, Restaurant/legal names, or menu identity.

The disabled acceptance harness starts at `B Main Branch` / version `2`; this local P2 made no Development write or credential operation.
