# Growth Loop

## Purpose

This document defines how Haocu can grow through product usage rather than only paid advertising.

## Core Growth Thesis

Food is naturally repeatable, visual, social, and local. Haocu should turn these properties into growth loops:

- meal analysis creates personal value;
- food diary creates memory;
- recommendations create repeated decisions;
- meal-buddy cards create invitations;
- restaurants create local network density;
- mascots and personality tests create shareable identity.

## Loop 1 — Meal Record Loop

```text
Analyze meal -> Save meal -> See today summary -> Receive next suggestion -> Analyze again
```

### Growth Mechanism

The more meals users save, the more useful recommendations become.

### Product Requirements

- Save flow must be fast.
- Today summary must update reliably.
- Food diary must make past data feel valuable.
- Recommendations must reference user history in simple language.

## Loop 2 — Taste Graph Loop

```text
Rate food -> Build taste profile -> Recommend better dishes -> User rates again
```

### Growth Mechanism

Private ratings improve personalization and reduce restaurant discovery risk.

### Differentiation

Unlike public review platforms, Haocu can recommend based on “people with similar taste liked this,” not just “many people rated this highly.”

## Loop 3 — Meal Buddy Loop

```text
Create meal-buddy card -> Invite/chat -> Meal happens -> Relationship or diary event -> More cards
```

### Growth Mechanism

Food intent lowers the awkwardness of meeting. Meal-buddy cards can invite new users into a specific action.

### Guardrails

- Avoid dating-app framing as the primary message.
- Keep chat-first preference visible.
- Preserve anonymous/free identity boundaries.
- Make cancellation and reporting flows available.

## Loop 4 — Restaurant Local Density Loop

```text
Users analyze dishes -> Restaurant/dish data improves -> Better restaurant recommendations -> More restaurant demand -> Restaurants participate
```

### Growth Mechanism

User behavior helps identify restaurants and dishes worth structuring. Restaurant participation then improves consumer recommendations.

## Loop 5 — Mascot and Personality-Test Loop

```text
User gets food personality/mascot -> Shares result -> Friends enter app/crowdfunding page -> More users create meal records
```

### Growth Mechanism

Mascots make nutrition and social identity lighter, more shareable, and less clinical.

### Requirements

- Mascot roles must map to meaningful food behavior.
- Anonymous avatar and premium real-person identity must remain distinct.
- Share content must not expose private health details without consent.

## Loop 6 — Crowdfunding Loop

```text
Crowdfunding story -> Early supporter reward -> Social proof -> App waitlist/download -> More demos and restaurant leads
```

### Growth Mechanism

Crowdfunding validates demand, funds MVP development, and creates public narrative.

## Anti-Growth Risks

| Risk | Effect | Mitigation |
|---|---|---|
| AI result feels wrong | User loses trust | Correction flow and confidence language |
| UI feels crowded | User stops before action | Clean hierarchy and one primary action |
| Social feels unsafe | User avoids meal-buddy | Opt-in boundaries and reporting |
| Premium feels blocked | User churns | Keep free core loop useful |
| Restaurant data feels fake | Investor/restaurant distrust | Plausible dish data and review notes |

## Growth Metrics

- invite conversion rate;
- shared result click-through;
- meal-buddy card creation per active user;
- restaurant card to action conversion;
- food diary revisit;
- waitlist/crowdfunding conversion;
- retention lift from social users vs non-social users.
