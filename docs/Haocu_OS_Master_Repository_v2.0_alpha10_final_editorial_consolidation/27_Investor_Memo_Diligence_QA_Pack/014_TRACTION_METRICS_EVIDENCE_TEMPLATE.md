# Traction Metrics Evidence Template

> Use: Investor-grade metrics table. Never mix demo, pilot, and live data without labeling.

## Metric Definitions

| Metric | Definition | Evidence Level |
|---|---|---|
| Analysis Start Rate | Users who start AI analysis / visitors or active users. | Pilot / Live |
| Analysis Completion Rate | Completed analysis / started analysis. | Pilot / Live |
| Correction Rate | Analyses with user correction / completed analyses. | Pilot / Live |
| Save Rate | Meals saved to diary / completed analyses. | Pilot / Live |
| Repeat Usage | Users returning within D1/D7/D30. | Pilot / Live |
| Recommendation Action Rate | Recommendation clicked/saved/used / recommendation shown. | Pilot / Live |
| Meal-Buddy Creation Rate | Meal-buddy cards created / eligible users. | Pilot / Live |
| Invite Acceptance Rate | Accepted invites / sent invites. | Pilot / Live |
| Restaurant Onboarding Time | Time to structure one restaurant profile. | Pilot |
| Restaurant Continuation Intent | Restaurants willing to continue after pilot / pilot restaurants. | Pilot |
| WTP Signal | Users indicating payment/preorder/pledge intent. | Pilot / Live |

## Investor Summary Format

During [period], Haocu tested [flow] with [sample]. The strongest signal was [metric/result]. The biggest limitation was [limitation]. The next experiment is [next test].

## Common Mistakes to Avoid

- Do not report total impressions as traction if users did not complete the core flow.
- Do not combine founder demo reactions with user retention metrics.
- Do not hide sample size.
- Do not describe survey interest as paid conversion.
- Do not claim AI accuracy without a defined test set.
