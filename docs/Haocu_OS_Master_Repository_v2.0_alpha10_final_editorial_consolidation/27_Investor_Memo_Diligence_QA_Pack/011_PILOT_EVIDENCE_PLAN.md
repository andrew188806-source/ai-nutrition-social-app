# Pilot Evidence Plan

> Purpose: Convert the product story into investor-grade evidence through controlled user and restaurant pilots.

## Pilot Philosophy

A pilot should answer a specific investment question. It should not try to prove the full platform at once.

The first pilot should focus on whether the core loop creates repeated user value:

1. User analyzes or logs meals.
2. User corrects/saves meal results.
3. User returns to food diary or recommendation.
4. User clicks, saves, or acts on recommendation.
5. User optionally creates meal-buddy/social intent.
6. Restaurant data improves recommendation confidence.

## Pilot Types

### A. User Pilot

| Objective | Metric |
|---|---|
| Understand meal analysis friction | analysis start → completion rate |
| Understand trust in AI results | correction rate and correction types |
| Understand memory value | repeat diary save / return rate |
| Understand recommendation value | recommendation click, save, or meal choice rate |
| Understand social appetite | meal-buddy card creation and invite acceptance |

### B. Restaurant Pilot

| Objective | Metric |
|---|---|
| Validate restaurant willingness | meetings, LOIs, pilot agreements |
| Validate menu data setup | menu items entered, nutrition fields completed |
| Validate value proposition | restaurant feedback on why they care |
| Validate operational burden | time to onboard one restaurant |
| Validate customer-facing utility | QR page views, card saves, recommendation clicks |

### C. Crowdfunding / Prelaunch Pilot

| Objective | Metric |
|---|---|
| Validate story | landing page conversion, email signup |
| Validate mascot/IP interest | test engagement, reward click rate |
| Validate willingness to pay | pledge intent, pre-order, survey |
| Validate acquisition channel | creator/referral/ads performance |

## Pilot Design Rules

1. Use small cohorts before broad launch.
2. Track actual behavior, not only opinions.
3. Separate demo praise from real usage retention.
4. Do not overclaim restaurant commitments.
5. Label all evidence by date, source, sample size, and limitation.
6. Capture objections and confusion, not only positive quotes.

## Red Flags to Watch

- users enjoy the first demo but do not return
- users distrust nutrition estimates and do not correct them
- users like recommendations but do not act on them
- meal-buddy matching creates safety concerns or product confusion
- restaurants want only free exposure and show no willingness to provide data or pay
- AI costs are too high for expected consumer pricing
