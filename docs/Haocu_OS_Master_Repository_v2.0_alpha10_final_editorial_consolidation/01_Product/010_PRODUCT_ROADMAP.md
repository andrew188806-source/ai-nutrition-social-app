# Product Roadmap

## Purpose

This roadmap organizes product development into practical releases while preserving the long-term Haocu vision.

## Roadmap Principles

1. Stabilize the core loop before adding breadth.
2. Treat AI correction data as a key asset.
3. Build restaurant surfaces only as deeply as needed for consumer value first.
4. Keep premium visible but not blocking.
5. Separate MVP, MVP+, beta, and future-phase commitments.

## Stage 0 — Repository and Demo Stabilization

### Goals

- Complete professional repository handoff.
- Convert PRD into engineering backlog.
- Clean UI and state bugs.
- Prepare demo for stakeholders and engineering team.

### Required Work

- Fix TypeScript errors.
- Replace `latestCorrectedMealRecord` with meal record collection.
- Unify meal-buddy and group-table data models.
- Add cross-platform storage adapter.
- Fix restaurant card navigation to created meal-buddy card.
- Fix chat list ordering and back navigation.

## Stage 1 — MVP Build

### Consumer Capabilities

- AI analysis flow.
- Correction and save.
- Today intake and food diary basics.
- Restaurant recommendation.
- Meal-buddy card and candidate flow.
- Premium/free distinction.
- Basic safety and privacy copy.

### Engineering Capabilities

- Stable mobile routes.
- Shared data store.
- Supabase schema design.
- API boundary.
- Analytics event plan.
- QA regression checklist.

## Stage 2 — Closed Beta

### Goals

- Test with early users.
- Validate repeat meal tracking behavior.
- Measure recommendation usefulness.
- Validate meal-buddy comfort and safety.
- Recruit first restaurant pilot partners.

### Enhancements

- Better personalization.
- More realistic restaurant/dish data.
- Improved correction UX.
- Notification reminders.
- Basic report/block flows.

## Stage 3 — Public Launch / Crowdfunding Support

### Goals

- Public narrative and early supporter conversion.
- App waitlist or public beta.
- Mascot/IP-driven sharing.
- Restaurant lead generation.

### Requirements

- Stable demo URL.
- Clear crowdfunding product packages.
- Investor and professional review package.
- Basic data room.

## Stage 4 — Restaurant Platform Expansion

### Goals

- Restaurant admin onboarding.
- Menu/dish data operations.
- Nutrition disclosure workflow.
- Partner analytics.
- Campaign surfaces with transparent labeling.

## Stage 5 — ESG / Supply Chain Expansion

### Goals

- Surplus and near-expiry food flow design.
- Dynamic pricing and logistics concepts.
- B2B operational pilots.
- Grant/subsidy alignment.

## Stage 6 — Household Nutrition App

### Goals

- Household meal planning.
- Community pickup/fresh pack model.
- Nutrition gap recommendation.
- Integration with restaurant/retail supply data.

## Roadmap Non-Commitments

The roadmap does not guarantee exact release dates. It defines strategic order. Dates should be added only after engineering estimation, funding status, and team capacity are known.
