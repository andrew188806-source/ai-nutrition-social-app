# Internal Team Read First

## Purpose

This file gives any internal contributor one shared rulebook for working from the frozen Alpha 10 repository.

## Internal Team Rules

1. Use Alpha 10 as the stable baseline.
2. Do not add new features to MVP without a documented founder decision.
3. Use standard terminology from `TERMINOLOGY_STANDARDIZATION.md`.
4. Do not overclaim evidence. Use Planned, Demo, Pilot, Live, Verified.
5. Keep mock/demo data separate from real data.
6. Send role-specific materials to external audiences.
7. Use `CLAIMS_AND_RISK_REVIEW.md` before writing public, investor, or restaurant-facing copy.
8. Use `FINAL_HANDOFF_CHECKLIST.md` before giving files to a new engineer, lawyer, investor, advisor, or partner.

## Internal Escalation Questions

- Is this a product decision or just a wording change?
- Is this MVP or future scope?
- Is the claim supported by evidence?
- Is this safe to share externally?
- Does this require legal, finance, privacy, nutrition, or IP review?

## Default Answer When Unsure

When unsure, mark the item as draft/internal, avoid external claims, and ask the founder to classify it before using it in a public or investor-facing context.
