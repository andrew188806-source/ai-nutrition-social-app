# Demo Readiness UI Review

## Purpose
Define checklist for making Haocu presentable to investors, restaurants, family/elders, and early engineers.

## Demo Story

A 3-minute demo should show:

1. Open home.
2. Take/upload meal photo.
3. See AI analysis and nutrition summary.
4. Save to today intake.
5. See next meal/restaurant recommendation.
6. Use this meal to create Meal Buddy card.
7. View candidates/chat/group table teaser.
8. Show Premium difference.

## Visual Checklist

- No broken English user-facing strings.
- No debug labels visible.
- No inconsistent avatars for same user.
- No duplicate CTA buttons.
- No crowded home screen.
- No hidden date selector at bottom of restaurant card flow.
- No wrong back navigation in chat.
- No stale placeholder data such as all dates fixed incorrectly except where intentional.

## Data Checklist

- AI result has realistic food.
- Meal summary updates after save.
- Restaurant recommended dishes match restaurant type.
- Meal Buddy cards reference same mock user pool.
- Chat list sorting demo works.
- Group table participants are consistent.

## Premium Demo Checklist

- Free anonymous mascot card visible.
- Premium real-person card clearly different.
- Feature limit difference visible.
- Paywall/locked state is clean and not overly aggressive.

## Acceptance Criteria

1. Demo can be completed without explaining broken UI.
2. Core value appears within first minute.
3. Data relationships look believable.
4. UI is clean enough for screenshots.
5. Known limitations are documented instead of hidden.
