# 020 Document Access Guide

> Repository Status: Haocu OS Master Repository v2.0 Alpha 8.  
> Purpose: Clean investor / advisor / accelerator / restaurant-partner data room.  
> Boundary: External-readable summary only. Not legal, tax, accounting, securities, nutrition, medical, patent, privacy, or investment advice. Sensitive internal drafts and unreviewed details are intentionally excluded.

## Purpose

This guide defines what to share with different external readers. The goal is to preserve clarity and confidentiality while giving serious reviewers enough information to evaluate Haocu.

## Access Levels

### Level 1 — Intro Packet

Use for warm intros, first angel calls, accelerator screeners, and casual strategic conversations.

Include:

- one-pager
- deck or deck text version
- 30-second / 3-minute pitch
- product demo script or demo video
- company overview

Do not include:

- full engineering backlog
- raw legal/IP drafts
- finance model details
- security notes
- unreviewed patent disclosure

### Level 2 — Clean Data Room

Use for serious investors, platform reviewers, potential advisors, and restaurant partners who need more context.

Include:

- full `26_Investor_Clean_Data_Room`
- selected Section 25 fundraising documents
- selected product and MVP summaries
- restaurant partner summary where relevant

### Level 3 — Technical / Professional Review

Use for technical investors, CTO advisors, lawyers, accountants, privacy reviewers, or IP counsel.

Include only the relevant sections:

- engineering: `23_Engineering_Backlog_Pack`
- professional review: `24_Professional_Review_Pack`
- legal/IP: selected `17_Legal_IP`
- finance: selected `18_Finance`
- compliance: selected `14_Compliance`

Apply redaction and confidentiality controls where appropriate.

### Level 4 — Internal Repository

Use only for founder, core team, and retained reviewers.

Includes:

- full master repository
- drafts
- internal decision logs
- raw risk notes
- IP/patent drafts
- technical/security details
- finance assumptions

## Suggested File Routing

| Reader | Send First | Send Later |
|---|---|---|
| Angel investor | one-pager, deck, clean data room README | fundraising summary, risk summary, roadmap, finance summary. |
| Accelerator | company overview, product overview, demo script | MVP scope, GTM summary, engineering readiness. |
| Restaurant partner | restaurant partner summary, product overview | demo script, partner FAQ, pilot checklist. |
| Technical advisor | engineering readiness summary | selected Alpha 7A backlog. |
| Lawyer/IP counsel | legal/IP status summary | selected Alpha 7B review files and internal patent queue. |
| Accountant/finance advisor | finance status summary | selected finance models and crowdfunding assumptions. |

## Naming Rule

When sharing files externally, keep the Alpha version in the file name or cover note. This prevents reviewers from treating old drafts as current.

## Clean Boundary

Do not send the full repository as a first response to interest. The full repository is powerful internally but too noisy and potentially sensitive externally.
