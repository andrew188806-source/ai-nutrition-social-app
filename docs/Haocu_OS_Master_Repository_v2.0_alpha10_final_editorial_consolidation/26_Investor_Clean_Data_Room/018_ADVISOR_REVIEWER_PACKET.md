# 018 Advisor Reviewer Packet

> Repository Status: Haocu OS Master Repository v2.0 Alpha 8.  
> Purpose: Clean investor / advisor / accelerator / restaurant-partner data room.  
> Boundary: External-readable summary only. Not legal, tax, accounting, securities, nutrition, medical, patent, privacy, or investment advice. Sensitive internal drafts and unreviewed details are intentionally excluded.

## Purpose

This packet helps potential advisors, professional reviewers, and experienced operators understand where Haocu needs guidance. It is cleaner than the full internal repository and should be used for first advisor conversations.

## Best-Fit Advisors

| Advisor Type | Why Needed |
|---|---|
| Consumer product advisor | Clarify MVP, retention, onboarding, and habit loop. |
| Technical / CTO advisor | Validate architecture, scope, sprint plan, AI/data design, and build sequence. |
| AI/nutrition reviewer | Review analysis wording, uncertainty, correction, and health-claim boundaries. |
| Privacy/legal counsel | Review privacy, terms, consent, data retention, and social safety requirements. |
| IP counsel | Review patent/trademark strategy and disclosure timing. |
| Finance/accounting advisor | Review runway, budget, crowdfunding accounting, cap table, tax implications. |
| Restaurant operator | Validate partner package, data intake burden, pricing, and operational fit. |
| Growth/crowdfunding advisor | Validate campaign story, rewards, pricing, and prelaunch funnel. |

## Suggested Review Questions

### Product

- Is the MVP narrow enough?
- Is food recommendation first and social second clear?
- Which flows are overcomplicated for first-time users?
- What should be removed before pilot?

### Engineering

- Is the proposed stack appropriate for MVP speed?
- Which parts should be mocked for demo versus built for pilot?
- What technical risks should be resolved in Sprint 1?
- What data model decisions could create later migration pain?

### Legal / Privacy / IP

- What public claims should be changed?
- What privacy/terms/consent language is required before pilot?
- What social safety controls are minimum viable?
- Should any patent/trademark action happen before crowdfunding?

### Finance / Fundraising

- Is the use-of-funds story credible?
- What evidence should unlock the next tranche or round?
- What should not be shown to investors yet?
- How should crowdfunding be separated from equity fundraising?

### Restaurant

- Is the partner pitch understandable?
- What data would restaurants actually provide?
- What would they pay for before large user traffic exists?
- What claims would restaurants object to?

## Advisor Meeting Format

1. Send company overview and product demo script before the call.
2. Start with a 3-minute product story.
3. Ask for critique, not validation.
4. Capture red flags and recommendations.
5. Convert accepted feedback into decision log items.
6. Do not promise equity, payment, or formal advisor title without written terms.

## Clean Boundary

Do not send raw patent drafts, detailed security notes, private valuation math, or unredacted internal risk documents in first advisor conversations.
