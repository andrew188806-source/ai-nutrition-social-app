# 011 Product Demo Script

> Repository Status: Haocu OS Master Repository v2.0 Alpha 8.  
> Purpose: Clean investor / advisor / accelerator / restaurant-partner data room.  
> Boundary: External-readable summary only. Not legal, tax, accounting, securities, nutrition, medical, patent, privacy, or investment advice. Sensitive internal drafts and unreviewed details are intentionally excluded.

## Demo Goal

The demo should show Haocu’s product logic in under three minutes:

**meal analysis → correction → private food memory → next-meal recommendation → optional Meal Buddy / restaurant action.**

The viewer should leave understanding that Haocu is useful even before social features are used.

## 3-Minute Demo Flow

### 0:00–0:20 — Opening

“Haocu helps Taiwan outside eaters decide what to eat next. It starts from what you actually ate, not generic ratings.”

Show the home screen with a clean Today Nutrition Summary and obvious AI analysis entry.

### 0:20–0:55 — AI Meal Analysis

Open the AI analysis flow. Show meal photo/upload or demo seed result. Explain:

- AI proposes a meal result and nutrition estimate.
- The user can choose from candidates or correct details.
- The product does not pretend AI is perfect.

### 0:55–1:20 — Correction And Save

Show correction or confirmation. Save the meal into today’s intake.

Narration:

“The correction matters because it becomes the user’s private taste and nutrition memory. Over time, Haocu learns from what the user actually eats and corrects.”

### 1:20–1:50 — Food Diary / Today Intake

Show saved meal and daily summary. Keep the screen uncluttered. Highlight that users can understand their current day without manually building a spreadsheet.

### 1:50–2:20 — Next-Meal Recommendation

Show recommendation card. Explain that recommendations can consider:

- recent intake
- taste preference
- restaurant/dish data
- location or meal context
- user plan/free-Premium limits

### 2:20–2:45 — Optional Meal Buddy

Show the Meal Buddy card creation or candidate screen. Emphasize:

“Social is optional. Users can stay anonymous in the free path or unlock verified identity options later. The app is food-first, not pressure-first.”

### 2:45–3:00 — Close

Close with:

“Haocu turns meals into memory, memory into recommendations, and recommendations into action — whether the user eats alone, with a friend, or through a restaurant partner.”

## What Not To Demo First

Avoid leading with:

- too many settings
- every Premium limit
- admin dashboards
- unfinished supply-chain features
- legal/patent claims
- medical or weight-loss promises
- dense internal backlog screens

## Backup Demo Path

If live demo is unstable, use:

1. static screenshots
2. narrated click-through video
3. seeded data path
4. short deck slide with the core loop

## Demo Success Criteria

- viewer understands the core loop
- demo does not crash or feel cluttered
- AI correction is shown clearly
- social feature feels optional and safe
- restaurant data angle is visible but not overcomplicated
- no unreviewed legal/medical/investment claims are made
