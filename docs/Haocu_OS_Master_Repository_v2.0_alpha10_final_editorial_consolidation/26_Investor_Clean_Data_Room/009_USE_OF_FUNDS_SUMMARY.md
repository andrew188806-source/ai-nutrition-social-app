# 009 Use Of Funds Summary

> Repository Status: Haocu OS Master Repository v2.0 Alpha 8.  
> Purpose: Clean investor / advisor / accelerator / restaurant-partner data room.  
> Boundary: External-readable summary only. Not legal, tax, accounting, securities, nutrition, medical, patent, privacy, or investment advice. Sensitive internal drafts and unreviewed details are intentionally excluded.

## Use-Of-Funds Principle

Funds should be tied to milestones and evidence. Do not present exact percentages externally until finance review confirms the fundraising amount, runway, hiring/contracting plan, taxes, accounting, and contingency requirements.

## Clean Budget Buckets

| Bucket | Purpose | External-Safe Explanation |
|---|---|---|
| Product / Engineering | Build and stabilize MVP | Mobile app, backend, database, AI integration, admin basics, QA, release readiness. |
| AI / Data | Improve meal analysis and recommendations | Database-first lookup, correction loop, personalization foundations, evaluation and cost monitoring. |
| Design / Demo | Make product understandable and demo-ready | UI cleanup, prototype polish, demo script, screenshots, onboarding clarity. |
| Legal / Compliance / IP | Reduce public launch and fundraising risk | Privacy, terms, nutrition/health claims, fundraising review, trademark/patent counsel input. |
| Restaurant Pilot | Validate partner side | Menu/dish data intake, partner onboarding, pilot feedback, restaurant-facing materials. |
| Growth / Crowdfunding | Validate demand | Landing page, campaign video/assets, community/influencer tests, early supporter operations. |
| Operations / Finance | Keep execution controlled | Accounting, admin tools, company setup tasks, contractor/vendor management. |
| Contingency | Preserve runway | Buffer for unexpected engineering, review, fulfillment, or launch delays. |

## Spending Discipline

- Product and engineering should dominate early spend.
- Professional review should happen before public claims are made.
- Growth spend should be staged after the core demo is reliable.
- Mascot goods and crowdfunding rewards must be cost-modeled before being promised.
- Restaurant pilot spending should be lean and evidence-focused.
- Founder runway should be explicit if included.

## Milestone Mapping

| Milestone | Funds Should Produce |
|---|---|
| Demo stable | reliable investor/customer demo and clear screenshots/video. |
| MVP core loop | working analyze/correct/save/recommend flow. |
| Closed pilot | user evidence and feedback. |
| Restaurant pilot | partner feedback and structured dish/menu data. |
| Review cleared | decision log for legal/privacy/claims/fundraising boundaries. |
| Crowdfunding ready | campaign assets, reward cost model, prelaunch audience. |

## Items Requiring Review Before Sharing Numbers

- specific raise amount
- runway duration
- salary/founder compensation assumptions
- contractor rates
- valuation and dilution
- tax/accounting treatment
- reward fulfillment costs
- legal/IP filing costs

## Investor Takeaway

The budget should show disciplined conversion of planning work into build, review, pilot, and demand evidence. The clean data room does not need to expose every internal line item in early conversations.
