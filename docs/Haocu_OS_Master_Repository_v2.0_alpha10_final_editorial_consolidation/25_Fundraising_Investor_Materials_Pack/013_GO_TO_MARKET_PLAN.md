# 013 Go-To-Market Plan

> Repository Status: Haocu OS Master Repository v2.0 Alpha 7C.  
> Purpose: Fundraising / investor / accelerator / partner communication package.  
> Boundary: Draft material only. All valuation, securities, legal, tax, nutrition, patent, privacy, and financial claims require professional review before external publication.

## Launch Philosophy

Start narrow, prove repeated behavior, then scale.

Haocu should not launch broadly before the core loop is stable. The first launch should validate whether users record meals, correct AI, trust recommendations, and optionally use Meal Buddy.

## Stage 0 — Demo Stabilization

Goal: create one reliable demo path.

Requirements:

- AI analysis demo does not crash.
- correction and save flow works.
- Today Intake updates correctly.
- recommendation changes based on saved meal.
- Meal Buddy card creation works.
- restaurant dish CTA works.
- UI remains clean and uncluttered.

## Stage 1 — Closed User Pilot

Target users:

- founder network
- office workers
- students
- outside eaters
- early supporters from food/fitness/social circles

Pilot questions:

- Do users complete meal analysis?
- Do they correct results?
- Do recommendations feel useful?
- Does nutrition summary feel helpful or annoying?
- Are users comfortable creating Meal Buddy cards?
- What Premium features create willingness to pay?

## Stage 2 — Restaurant Pilot

Target restaurants:

- healthy lunch boxes
- cafes
- light meals
- casual restaurants with structured menus
- restaurants with clear dish photos

Pilot deliverables:

- restaurant intake sheet
- menu data structure
- dish/nutrition cards
- QR page concept
- restaurant feedback session
- partner case study draft

## Stage 3 — Crowdfunding Validation

Goals:

- validate brand story
- validate early supporter willingness
- test Premium/package demand
- build community list
- create public accountability for MVP

Required before launch:

- legal/consumer review
- reward cost model
- delivery timeline
- founder story
- demo video
- FAQ and risk disclosure

## Stage 4 — District-Focused Beta

Start with one or a few districts. Do not try to cover every restaurant.

Beta goals:

- user retention
- meal record volume
- recommendation feedback
- restaurant data completion
- Premium conversion signal
- social safety incidents and moderation readiness

## Channel Strategy

| Channel | Purpose |
|---|---|
| Founder demos | Close advisors, pilot restaurants, early investors |
| Food communities | Early user testing and qualitative feedback |
| Campus/office networks | Dense outside-eating users |
| Restaurant partners | Structured data and local credibility |
| Crowdfunding | Demand validation and brand launch |
| Short-form content | Education and mascot-led awareness |

## GTM Metrics

- waitlist signups
- pilot activation rate
- weekly active meal records
- correction completion rate
- recommendation engagement
- Meal Buddy creation rate
- restaurant pilot completion
- crowdfunding conversion
- Premium preorder interest
