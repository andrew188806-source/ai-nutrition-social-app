## Restaurant Partner Summary

Haocu is designed to help Taiwan-first food consumers better understand meals, record preferences, discover restaurants, and optionally connect with meal companions. Restaurant partners may benefit from clearer menu/nutrition presentation, AI-assisted recommendation surfaces, pilot visibility, and structured user feedback.

## Partner Conversation Boundaries

- The current repository contains planning, demo, and pilot-preparation materials.
- Restaurant-partner claims must distinguish between planned, demo, pilot, live, and verified status.
- Nutrition and menu data responsibilities must be clarified before public use.
- Any commercial pilot should define scope, data rights, liability, responsibilities, time period, and success metrics.

## Restaurant Pilot Topics

| Topic | Suggested Question |
|---|---|
| Menu data | Which menu items, ingredients, portions, allergens, and pricing can be provided? |
| Nutrition display | What level of nutrition disclosure is acceptable and reviewable? |
| Customer flow | Should the pilot focus on QR menu, recommendation, meal logging, or dining social flow? |
| Operational burden | Who updates menu changes and how often? |
| Success metrics | What would make the pilot useful for the restaurant? |
| Brand safety | What should Haocu avoid saying publicly before approval? |

## What To Share With Restaurants First

For early conversations, share a short partner explanation, demo screenshots/walkthrough if available, and pilot discussion notes. Avoid sending the full internal repository unless the restaurant is a strategic partner under appropriate confidentiality expectations.
