## 1. Summary

- 98 registry routes: **8 LIVE, 17 DEMO, 73 NOT_ENABLED**. 97 have a page; `/admin/break-glass` is a registry-only reservation.
- Eight `/admin` pages render real data: six Platform Management pages and, since ADMIN-A, `restaurant-branch-status` and `audit-platform-memberships`. Every other `/admin` page is a scaffold (`AdminRoutePlaceholder`/`AdminRegistryPage`); DEMO means "mock UI exists on the legacy root successor".

All deferred families still fall back to base-Admin scaffolds (unchanged, no data).
- Column legend — *State*: registry availability, with PLACEHOLDER for a scaffold with no backend. *Data source*: for the `/admin` page (REAL_LIVE / MOCK / NONE / STATIC). *AE1*: needs an ADMIN-AE1 CURRENT read key before real data may be shown.

Envelope `{state: ready|forbidden|invalid_request|not_found, ...}`; lists take `p_limit` (default 20, 1..50) and `p_offset` (default 0, 0..10000), out-of-range values are rejected (never clamped), total ordering `(name, id) collate "C"`, response `{items, limit, offset, hasMore}`. Draft/archived/inactive rows are visible (no Consumer-public filter); child ids are always validated against the parent Restaurant.
