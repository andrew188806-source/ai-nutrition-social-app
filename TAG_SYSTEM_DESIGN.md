# Tag System Design

## Tag Categories

- eating_habit
- health_goal
- social_intent
- restaurant
- meal
- menu_item

## Product Value

Tags are not decoration. They power:

- next-meal recommendation
- Community Card compatibility
- social profile unlock value
- Health Goal Mode
- restaurant discovery
- sponsored recommendation filtering
- admin risk review

## Compatibility Logic

MVP mock logic compares shared eating habit tags, health goal tags, social intent tags, recent meal pattern and restaurant/menu tags. Premium mode reveals deeper explanations; Free mode shows partial anonymous reasons.

## Governance

Health tags must avoid disease-treatment claims. Sponsored tags must be labeled. Social intent tags must stay focused on healthy eating companionship rather than dating-first positioning.
## Phase 6 Matching Corrections

Tags support both nutrition and social eating discovery. They should never be decorative only.

Contextual matching priority:
1. Same restaurant overlap: selected today, recently eaten, or saved.
2. Health goal compatibility: fat loss, high protein, balanced eating, healthy dinner.
3. Tag compatibility: meal style, lifestyle, social intent, and restaurant/menu tags.
4. Nearby status or approximate distance.

Meal payment preference can lightly affect compatibility:
- Same preference slightly increases confidence.
- Different preference shows a gentle planning reminder.
- Matching is never blocked only because of payment preference.

Community Card is a tag-powered matching profile. It is not a broad social feed.

Sponsored tags must remain visibly labeled and distinguishable from organic compatibility tags.
